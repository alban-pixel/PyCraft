> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Survival mode: an item registry, mining times and drops, tools, crafting, a furnace, health, and the inventory, crafting and furnace screens. Creative mode is kept.

**Architecture:** Pure-Python modules that don't need GL or Pyxel input, each tested on its own: `items.py`, `recipes.py`, `inventory.py`, `survival.py`, `furnace.py`, and `screens.py` (its layout and input logic). `main.py` only wires them in. Item icons get their own image bank.

**Tech Stack:** Python 3.14, numpy, Pyxel, pytest.

**Spec:** [`docs/superpowers/specs/2026-11-16-survie-design.md`](../specs/2026-11-16-survie-design.md). It is binding: every value it pins (hardness groups, tool table, recipes, smelting, fuel, drops, health rules, save keys) is copied from it, not invented.

## Global Constraints

- Work in `pycraft-gpu/`. Run tests with `.venv/bin/python -m pytest tests -q` (pytest is already installed). The whole suite must stay green; 113 tests pass today.
- An item is an `int`. 0 to 255 are blocks (the same numbers as `blocks.py`; 0 is empty). 256 and up are non-block items. A stack is a tuple `(item, count, damage)`; an empty stack is `(0, 0, 0)`.
- Never write to `~/.pyxel` or open a game window. A headless run uses `main.App(headless=True)`; avoid it unless the brief asks for it.
- Code style: follow the existing modules. Comments and docstrings in plain English, explaining why; lines of 120 characters at most; no new dependencies.
- New block ids are appended after `PISTON_HEAD`, and new tile ids after `T_PISTON_INNER`. Don't renumber anything (saves store the numbers).
- Commit after each task, with a message in the repo's style (an imperative sentence), ending with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Old saves** (no `mode` key; a `hotbar` of 9 block ids): they load in Creative with those blocks, and nothing crashes (Task 8).
2. **A full inventory**: breaking a block whose drop doesn't fit loses it with a message; closing a screen whose grid can't go back loses the excess with a message (Tasks 3 and 8).
3. **A tool breaking mid-mining**: the slot empties and mining goes on by hand (Tasks 3, 5 and 8).
4. **Breaking a lit furnace with items in it**: the contents go to the inventory, and the furnace entry disappears (Tasks 6 and 8).
5. **Switching between Survival and Creative with `/gamemode`**: flying stops in Survival, health is untouched in Creative, and the inventory is kept (Task 8).

### Task 3: The inventory and its clicks (`inventory.py`)

**Files:** Create `inventory.py`; Test `tests/test_inventory.py`.

**Interfaces:**
- Consumes `items.max_stack`, `items.TOOLS` and `recipes.match`.
- Produces:
  - `EMPTY = (0, 0, 0)`, `HOTBAR = range(0, 9)`, `MAIN = range(9, 36)` ;
  - `class Inventory`:
    - `__init__()` gives 36 empty slots ; `slots: list[tuple[int, int, int]]` ;
    - `add(item, count, damage=0) -> int` returns what didn't fit. It tops up existing stacks of the same item first (hotbar, then main), then fills empty slots (hotbar first, then main). Tools never stack ;
    - `remove_from(i, n)` ;
    - `damage_tool(i, amount=1) -> bool`: True when the tool broke (the slot empties) ;
    - `to_array() -> np.ndarray` of shape (36, 3), int32 ;
    - `@classmethod from_array(arr)`.
  - `click(slots, cursor, i, button) -> tuple[list, tuple]`: pure, returns new lists. `button` is `"left"` or `"right"`. The rules are the spec's (left: take the whole stack, put all, merge up to `max_stack`, or swap; right: take half rounded up, or put one).
  - `shift_click(slots, i, targets) -> list`: moves the stack at `i` into `targets` (a list of slot indices, in order), merging first and then using empty slots ; what doesn't fit stays.
  - `grid_items(slots, start, size) -> list[list[int]]`: the item ids of a `size`×`size` grid stored in `slots[start:start + size*size]`, row by row.
  - `take_result(grid_slots, size, cursor) -> tuple[list, tuple, bool]`: crafts once into the cursor when allowed (the cursor is empty, or holds the same item with room for the whole result), removing 1 from each non-empty grid slot. Returns the new grid, the new cursor, and whether it crafted.
  - `craft_all(grid_slots, size, inv) -> list`: crafts repeatedly into `inv` (through `add`) while the recipe still matches and the whole result fits. Returns the new grid.
  - `give_back(inv, stacks) -> int`: puts stacks back with `add`, and returns how many items were lost.

### Task 6: The furnace (`furnace.py`)

**Files:** Create `furnace.py`; Test `tests/test_furnace.py`.

**Interfaces:**
- `@dataclass class FurnaceState`:
  - `slots: list` of 3 stacks: 0 input, 1 fuel, 2 output ;
  - `burn_left: float = 0` and `burn_total: float = 0` (in ticks) ;
  - `cook: int = 0` (ticks toward `COOK_TICKS`).
- `class Furnaces`:
  - `states: dict[tuple, FurnaceState]` ;
  - `get(pos) -> FurnaceState` (created on first use) ;
  - `remove(pos) -> list[stacks]` (the non-empty stacks) ;
  - `tick(sim)`, run once per simulation tick (registered with `sim.every_tick.append(furnaces.tick)`).
  - For each state, `tick` does the following:
    - when it isn't burning (`burn_left <= 0`) and the input can smelt into the output (empty, or the same item with room) and the fuel slot holds fuel: it burns 1 fuel, `burn_total = burn_left = fuel_value × COOK_TICKS` ;
    - while burning, `burn_left -= 1`, and `cook += 1` when the input can smelt; at `COOK_TICKS`, it moves 1 input to the output and resets `cook` to 0 ;
    - when it can't smelt, `cook` resets to 0 ;
    - the block at `pos` is set lit (`blocks.LIT_FURNACE`) while `burn_left > 0`, and unlit (`UNLIT_FURNACE`) otherwise, through `sim.set_block`, keeping the state byte ;
    - a state whose block isn't a furnace any more (lit or not) is dropped.
  - `to_array() -> np.ndarray` (n, 13), int64 rows: `x, y, z`, the 3 stacks as `(item, count)` pairs (damage isn't kept: furnace contents never hold tools), `burn_left`, `burn_total`, `cook`.
  - `@classmethod from_array(arr)`.
